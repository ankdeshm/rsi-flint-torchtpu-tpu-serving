# `RecursiveSI/flint` (`40B-A2.5B` MoE) Serving on TPU `v7x-16` & `v5p-16`

Serving configurations (**`sglang-torchtpu`** sub-host zero-ICI `TP×DP` and **`vllm-torchtpu` `v0.32.0`** multi-host Ray `EP=32`/`EP=16`), `[128, 128]` dynamic Block-FP8 checkpoint converter, fused VMEM Pallas `router_topk` (`256`-expert) & RPA v3 (`head_dim=128`) `attention_sink` kernels, sub-host VFIO / metadata replica isolation, prefix-trunk affinity HTTP gateway, and serving benchmarks up to **`131,072` (`128K`) context** for **[`RecursiveSI/flint`](https://huggingface.co/RecursiveSI/flint)** (`39.8B` total / `~2.5B` active MoE) on **Google Cloud TPU `v7x-16` (`2x2x4`)** and **TPU `v5p-16` (`2x2x4`)**.

## 3. Methodology Notes

1. **Throughput Definition & Excluded Warm-Up:** Output throughput (`tok/s`) equals completed output tokens divided by steady-state measurement `wall_sec`. For cached (`50%` / `80%` / `95%`) points, shared prefix trunks are pre-warmed prior to starting the timer (`prewarm_sec` is `1.1–1.7 s` at `4K`, `19–36 s` at `64K`, and `51–99 s` at `128K` on `v7x-16`, and `1` warm-up request on `vLLM`), and pre-warm duration is excluded from `wall_sec`. Total throughput (`slice_total_tok_s` / `total_tok_s`, e.g., `130,432.8` tok/s on `vLLM BF16`) includes prompt tokens from cached prefixes.
2. **Prefix-Cache Routing & Observed Hit Rates:**
   - On `v7x-16` `sglang-torchtpu`, the benchmark client attaches `X-Trunk-Index` headers (`v7x/scripts/bench_flint_v7x.py`) so `gateway_flint_v7x.py` routes each request to the replica pool holding that pre-warmed prefix trunk (oracle prefix-affinity routing). Server-side observed cache hit rates were not recorded in `v7x` result JSONs (`observed_cache_hit_pct=null`).
   - On `v5p-16` `sglang-torchtpu`, observed prefix cache hit rates were recorded per row (`93.75%` at `4K`, `94.53%` at `8K`, `94.92%` at `64K`, and `94.97%` at `128K` for `95%` target prefix).
   - On `vllm-torchtpu` (`EP=32` / `EP=16`), requests enter a single `vllm serve` endpoint using internal Ray Data-Parallel Load Balancing (not prefix-affinity routed), and server-side cache hit counters were not recorded per row.
3. **Requests per Point (`n`) & Single-Wave Points:**
   - `sglang` `DP-Attn=32` and `BF16 mrr=96` (`v7x-16`) and `v5p-16` `mrr=96`/`mrr=64` (`4K`–`8K`) send `n = 2c` requests (`n = 1.5c = 1536` at `c=1024`).
   - Several peak rows are **single-wave (`n = c`)** measurements: `sglang Block-FP8 TP=2×DP=16` at `c=512` (`n=512`, sweep stopped at `c=512`), `vLLM` `v7x-16` at `c=1024` (`n=1024`), `v5p-16` `128K` at `c=32` (`n=32`), and `v7x` single-host Multi-LoRA at `c=64` (`n=64`).
   - Every `v7x` `64K` and `128K` point with `c >= 64` sent **`n = 64` total requests**, capping effective concurrency at `64`.
4. **Repeats & Run-to-Run Spread:** Most cells represent a single pass. Where two passes were recorded (`BF16 TP=2×DP=16 mrr=96` at `4K:1K, 95%, c=768`), output throughput varied by `8.6%` (`32,517.7` vs `35,581.0` tok/s).
5. **Failed Requests:** Timed-out or HTTP 500 requests contribute `0` completed tokens to the numerator; any point with `failed > 0` is excluded from primary `0`-failure headlines or explicitly annotated with its failure count.
6. **Point Count Breakdown (`2,034` Top-Level Rows / `2,214` Including Nested Archives):** `774` rows in `v7x/results/*.json`, `831` rows in `v5p/results/raw/*.jsonl` (`821` sweep/slice + `10` smoke), `145` rows in `vllm/results/**/*.json`, and `284` top-level rows in `multilora_singlehost_opt/{v7x,v5p}/*.json` (`2,034` top-level rows total, plus `180` nested rows across `E_sglang_flint_multilora.json` [`80`], `pod2_v5p_tp_dp_and_specdec.json` [`36`], and `pod3_v5p_radix_swa_longctx.json` [`64`] = `2,214` total rows).

## 4. Supported Configurations & Known Limitations

- **Quality & Accuracy Evaluation Scope:** Each serving run verified functional generation on 1 Python `merge_intervals` coding unit test and 1 long-context passkey needle (`51,368` prompt tokens), and Multi-LoRA runs verified 3 qualitative prompts per adapter. Multi-hundred-sample accuracy benchmarks (e.g., `GSM8K`, `HumanEval`, `MMLU-Pro`) have not yet been run to quantify accuracy deltas across `Block-FP8`, `FP8` KV, `W8A16`, or `INT8 W8A16`.
- **Unsupported Single-Host `sglang-torchtpu` Configurations:**
  - `TP=1` on `v7x` (`A2_fp8_tp1_dp8`, `smoke_fp8_tp1_1rep`): `torch_tpu` raises `RuntimeError: No TPU topology found for count: 1` for single-TensorCore sub-chip meshes on dual-core `v7x`.
  - `Block-FP8 TP=8` without `EP` (`A4_fp8_tp8_dp1`): routed expert `moe_intermediate_size = 512` shards to `512 / 8 = 64 < 128`, violating `block_n = 128` (`TP=8 × EP=8` in `A5_fp8_tp8_ep8` resolves this by keeping unsharded `[512, 2048]` experts per rank).
  - `DP-Attention + EP=8` on single host (`A6_fp8_dpattn8_ep8`): `dp_size * tp_size = 32 > 8` single-host TensorCores in current launcher configuration.
  - `NGRAM` speculative decoding on `sglang-torchtpu` (`B1`, `B2`, `B2-EP`, `v5p_fp8_tp4_ngram4_probe`): `sglang_tpu` raises `NotImplementedError` (`NGRAM` not supported on TPU; only `EAGLE`/`EAGLE3`/`NEXTN`/`DFLASH`).
  - `moe_runner_backend=pallas_tpu_fused_rs` (`C4`), online `--quantization w8a8_int8` (`C5`), and `chunked_prefill_size=16384, mrr=128` (`D4`): unsupported or exceed HBM compilation budget on single-host `v7x`.
- **Speculative Decoding on `vllm-torchtpu` (`ngram`, `k=5`):** Requires `--no-async-scheduling` on `v0.32.0`, introducing a synchronous host-device step barrier (`18.91–19.62 ms` `p50` `TPOT` on `4K:1K` and `43.37–80.99 ms` on `coding_edit`, `~1.8×` slower per token than `TP=2` without speculation at `10.37 ms`). No matched `TP=4` non-speculative `--no-async-scheduling` baseline was measured, and acceptance rates are not recorded in the result JSON.
- **Multi-LoRA & QLoRA Serving Constraints:**
  - `vllm-torchtpu` (`v0.32.0`) rejects TPU LoRA when `tensor_parallel_size > 1`, `data_parallel_size > 1`, or on MoE models (`E3_vllm_torchtpu_flint_comparison.json`).
  - `sglang-torchtpu` compiled Multi-LoRA was benchmarked on single hosts (`v7x` `TP=2×DP=4`, `v5p` `TP=4×DP=1`) with attention-only `r=16` (`q/k/v/o_proj`) adapters on `BF16` or `Block-FP8` base weights; expert-layer/`r=64` adapters, quantized `INT8`/`NF4` base serving, and 4-host full-slice Multi-LoRA were not measured, and `4_loras_all_mixed` exhibited early EOS (`75–88%` of `512` requested tokens).
- **Long-Context Coverage:** `v7x` `64K`/`128K` sweeps cap `n=64` requests (`c <= 64` effective concurrency), and `v5p-16` `mrr=96`/`mrr=64` slice runs measured `64K`/`128K` at `95%` prefix cache only (`0%` long-context `v5p-16` slice points exist only in the baseline `v5p16_sweep_r1` `TP=2/4` runs and `vLLM` `c=4..8` runs).
